# 레지스트리 항목별 설명

레지스트리는 화면 왼쪽에 있는 탭 모음입니다. 프로젝트에 있는 스킬과 에이전트가
종류별로 나뉘어 들어 있습니다. 이 문서는 탭마다 무엇이 들어가는지, 어떤 파일이 되는지,
언제 골라야 하는지를 설명합니다.

- 캔버스·블랙보드 같은 기본 개념은 [핵심 컨셉](01-concept.md)을 먼저 보세요. 블랙보드 자세한 사용법은 [블랙보드](03-blackboard.md).
- 빌드 타깃 차이는 [LOCAL과 MARKETPLACE](04-local-vs-marketplace.md), LOCAL에서만 되는 기능은
  [LOCAL 전용 기능](05-local-only-features.md)에 있습니다.
- MCP로 같은 작업을 하는 방법은 [MCP 가이드](06-mcp.md)와 [MCP 도구 지도](../MCP.md)에 있습니다.

탭 라벨은 아이콘 하나뿐입니다. 마우스를 올리면 전체 이름이 보입니다.

| 탭 | 이름 | 한 줄 요약 |
|----|------|-----------|
| ⚙ | PROCEDURAL | 워크플로의 한 단계. 메인 대화에서 실행됩니다 |
| 🍴 | SYNC FORK | 워크플로의 한 단계. 서브에이전트에서 실행되고 **부른 쪽이 기다립니다** |
| 🍴⏳ | ASYNC FORK | 같은 fork인데 **기다리지 않습니다** — 보고가 나중에 작업 알림으로 옵니다 |
| 📄 | DECLARATIVE | 배경 지식. 캔버스에 놓지 않습니다 |
| ⚡ | TRANSFER | 전이(화살표) 위에서 실행되는 짧은 지침 |
| 📖 | REFERENCE | 노드에 붙이는 참조 문서. 여러 번 놓을 수 있습니다 |
| 🤖 | AGENTS | 별도 컨텍스트에서 일하는 서브에이전트. 캔버스에 놓습니다 |
| 🧩 | FORK AGENTS | fork 스킬이 **실행될 자리**. 캔버스에 놓지 않습니다(드래그할 수 없습니다) |
| 🔌 | EXTERNAL AGENTS | 다른 플러그인의 에이전트를 내 워크플로 노드로. 파일을 만들지 않습니다 |

## 공통 조작

어느 탭에서나 똑같이 동작합니다.

- **"+" 버튼**: 이름을 묻고 새 항목을 만듭니다. 이름이 겹치면 다시 묻습니다.
  이름은 소문자·숫자·하이픈(`my-skill`)으로 짓는 것이 좋습니다. 규칙에 맞지 않아도 편집 중에는
  경고만 뜨지만, 컴파일할 때는 에러가 나서 막힙니다.
- **더블클릭**: 편집기 탭을 엽니다. 이미 열려 있으면 그 탭으로 이동합니다.
- **캔버스로 드래그**: 워크플로 노드로 놓습니다. 종류에 따라 일반 노드가 되기도 하고,
  참조 노드가 되기도 하고, 아예 놓을 수 없기도 합니다(탭별 설명 참고).
- **배치 표시**: 이미 캔버스에 놓인 항목은 **기울임꼴 + 흐린 색**으로 바뀌고 다시 드래그할 수
  없습니다. 한 스킬은 한 자리에만 놓이기 때문입니다. 캔버스에 놓지 않는 종류(📄, ⚡)는 항상
  기울임꼴입니다.
- **우클릭 → 컴파일 미리보기…**: 이 항목이 어떤 파일로 나가는지 보여 줍니다. 파일은 쓰지 않습니다.
  ⚡ 전이 스킬처럼 캔버스 노드가 없는 항목도 여기서 미리 볼 수 있습니다.
- **우클릭 → 삭제**: 먼저 확인을 받고 지웁니다. 캔버스에 놓인 노드와 연결된 전이도 함께
  사라집니다. **Ctrl+Z로 되돌릴 수 있습니다.** 다른 설정에 이름으로 적힌 참조(예: 에이전트의
  `skills` 목록)는 몰래 지우지 않고 남겨 두며, 검증 패널에 경고로 뜹니다.
  🔗 랩핑 스킬은 삭제 대신 **비활성화**만 할 수 있습니다.

> 편집기는 공통으로 **프론트매터**(이름·설명·모델 등 설정), **본문**, 오른쪽 **보조 패널**로
> 이루어집니다. 오른쪽에는 항상 "이 스킬 전용 파일" 패널이 있어서, 스킬과 함께 나갈 파일을
> 본문으로 드래그해 넣을 수 있습니다.

## ⚙ PROCEDURAL — 절차형 스킬

**무엇인가.** 워크플로의 기본 단계입니다. "이 순서로 이 일을 해라"라는 작업 지침이
본문에 들어갑니다. 메인 대화에서 실행되므로 사용자와 주고받을 수 있습니다.

**산출 파일.** `skills/<이름>/SKILL.md` (LOCAL은 `.claude/skills/<이름>/SKILL.md`).
캔버스에 놓으면 컴파일러가 본문 뒤에 "다음 단계", "진입 맥락", "작업 재개" 같은 단락을
자동으로 붙입니다.

**언제 쓰나.**
- 사용자에게 확인을 받거나 대화가 필요한 단계 — 예: "요구사항 인터뷰", "초안 검토 받기"
- 결과를 메인 대화에 남겨 두고 싶은 단계
- 무거운 탐색이라 메인 컨텍스트를 아끼고 싶다면 🍴 SYNC FORK / 🍴⏳ ASYNC FORK를 고르세요.

**캔버스.** 드래그하면 일반 노드가 됩니다. 한 번만 놓을 수 있습니다.

**편집기 주요 패널.**
- **⇄ Transfer On (출력 포트)**: 이 단계가 끝나고 나갈 갈래입니다. 기본은 `done` 하나입니다.
  예: `approved` / `rejected` 두 포트를 만들고 캔버스에서 각각 다른 노드로 이으면 분기가 됩니다.
  포트 설명(description)에는 그 갈래로 **무엇을 넘기는지** 적습니다.
- **🤖 Agent Call (에이전트 호출 포트)**: 에이전트를 부를 때 씁니다. **에이전트 노드로 가는 전이는
  이 포트에서만 나갈 수 있습니다.** 설명에는 에이전트에게 넘길 내용을 적습니다.
- **진입 설정** (프론트매터 콤보, 캔버스 노드 우클릭 "진입점 설정"과 같은 기능):

  | 프리셋 | 뜻 | 언제 |
  |--------|-----|------|
  | 진입점으로 | 사용자도 모델도 시작 가능 | 워크플로 첫 단계 |
  | 유저 전용 진입점으로 | `/스킬`로만 시작 | 모델이 멋대로 시작하면 곤란한 작업 |
  | 순수 상태로 | 모델 호출로만 들어옴 | 체인 중간 단계 |
  | 일반 상태로 | 설정 안 함 (Claude Code 기본값) | 독립 스킬 |

  진입점으로 지정한 노드는 캔버스에서 금색 테두리와 🚪 뱃지로 보입니다.
- **종류 전환** 버튼: 절차형 · 동기 fork · 비동기 fork 사이를 오갑니다. 아래 🍴 참고.

**주의할 점.**
- 출력 포트가 하나도 없으면 에러입니다.
- 앞 단계에서 들어오는 전이가 있는데 사용자가 `/스킬`로 바로 시작할 수 있으면 경고가 뜹니다.
  중간 단계는 "순수 상태로"를 고르세요.

## 🍴 SYNC FORK / 🍴⏳ ASYNC FORK — fork 스킬 2종

**무엇인가.** 절차형 스킬과 똑같이 워크플로 단계지만, **서브에이전트에서 실행**됩니다.
스킬 본문이 그 서브에이전트의 작업 지시가 됩니다. 이 서브에이전트를 **fork 에이전트**라고 부릅니다.

**왜 두 종류인가.** 프론트매터 `background` 값이 실행 형상을 통째로 바꿉니다.

| | 🍴 SYNC FORK | 🍴⏳ ASYNC FORK |
|---|---|---|
| `background` | `false` | `true` |
| 부른 쪽 | 보고를 **기다립니다** | 기다리지 않습니다 — 보고가 나중에 **작업 알림**으로 옵니다 |
| 언제 | 결과가 있어야 다음 단계를 고를 수 있을 때 | 결과를 나중에 받아도 되는 곁가지 작업 |
| 캔버스 색 | 구리색 🍴 | 진한 구리 🍴⏳ |

`background`와 `context`는 **종류가 정합니다** — 편집기에 칸이 없고 여러분이 고칠 수 없습니다.
종류를 바꾸면 값이 따라 바뀝니다.

> **비동기라도 항상 비동기는 아닙니다.** Claude Code는 네 경우에 `background: true`를 무시하고
> 그 자리에서(동기로) 돌립니다 — 비대화 `claude -p`/Agent SDK 실행, `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`,
> 같은 스킬이 아직 도는 중의 재호출, 스케줄 작업이 발화한 실행. 그래서 산출 문구도 "기다리지 않는다"고
> 단정하지 않고 두 경로를 다 말합니다.

**산출 파일.** `SKILL.md` 하나입니다. 프론트매터에 `context: fork` → `agent:` → `background:`가
이 순서로 들어갑니다. 에이전트 파일을 새로 만들지는 않습니다.

**언제 쓰나.**
- 파일을 많이 읽는 조사·분석처럼 메인 컨텍스트를 더럽히기 싫은 단계 — 예: "코드베이스에서 관련 파일 찾기"
- 결과 요약만 받으면 되는 단계
- 사용자와 대화해야 하는 단계라면 ⚙ PROCEDURAL이 맞습니다. fork 에이전트는 사용자에게 되묻지 못합니다.

**fork 에이전트 고르기** (프론트매터 AGENT 칸, 설명 바로 아래에 있습니다). 고를 수 있는 것은 세 종류뿐입니다.
1. **내장 에이전트** — `general-purpose`(기본값), `Explore`, `Plan`
2. **사용 선언한 외부 플러그인의 에이전트** — `플러그인:이름` 형식
3. **프로젝트의 🧩 fork 에이전트** — 아래 🧩 FORK AGENTS 탭에서 만든 것

🤖 AGENTS 탭의 **워크플로 에이전트는 고를 수 없습니다.** 그쪽은 캔버스 노드로 불리는 종류이고
fork 에이전트는 fork 스킬의 실행 기반이라 아예 다른 물건입니다(배치 여부와 무관합니다 —
예전에는 "캔버스에 놓지 않은 에이전트"면 고를 수 있었는데, 그러면 배치를 지우기만 해도 조용히
겸직이 생겼습니다). 워크플로 에이전트 이름을 적으면 그 사실을 말하며 거부합니다.

**설정 우선순위.** 도구는 fork 에이전트 설정을 따릅니다. 그래서 fork 스킬에는 `allowed-tools` 칸이
없습니다. 모델·effort는 이 스킬 값이 이기고, 비워 두면 fork 에이전트 값을 씁니다.

**캔버스.** 출력 포트·에이전트 호출 포트·진입 설정은 절차형과 같습니다. 캔버스에 놓인 fork 스킬은
끝나면 메인 대화에 **보고**를 돌려주고, 메인이 그 보고를 보고 다음 갈래를 고릅니다. fork 스킬
자신은 진행 기록을 쓰지 않고 다음 단계도 시작하지 않습니다.

**비동기 fork의 진행 기록 규약.** 진행 파일은 플러그인당 항목이 하나뿐이라 "지금 도는 비동기 단계"를
적을 자리가 없습니다. 그래서 컴파일러가 세 자리에 규약을 넣습니다.
1. **넘기는 쪽**이 `--current <그 fork> --note "awaiting background fork"`를 기록하고 기다리지 않습니다.
2. **비동기 fork의 보고**는 진행 명령 앞에 선행 조건을 답니다 — "먼저 읽어 보고 `current`가 아직 나면
   실행하고, 워크플로가 이미 지나갔으면 진행 파일을 건드리지 말고 사용자에게 결과만 보고하라".
3. **워크플로 가이드의 재개 규칙**이 "아직 도는 비동기 fork가 `current`면 사용자에게 확인할 일이
   아니다 — 보고를 기다리는 중이라고 알려라"라고 말합니다.

**종류 전환은 3-way입니다** (절차형 ↔ 동기 fork ↔ 비동기 fork). 편집기 버튼, 캔버스 노드 우클릭
"종류 전환", MCP `convert_skill` 중 아무거나 쓰면 됩니다. 이름·본문·포트·전이·배치는 그대로 유지되고
Ctrl+Z 한 번으로 되돌아갑니다. 버리는 값은 전환 쌍이 정합니다.

| 전환 | 버리는 값 |
|------|-----------|
| 절차형 → fork(둘 중 아무거나) | `allowed_tools` (fork에서는 효과가 없습니다) |
| fork → 절차형 | `agent` |
| 동기 fork ↔ 비동기 fork | **없습니다** — `agent`가 그대로 따라옵니다 |

열려 있던 편집 탭의 프론트매터 폼과 레지스트리는 **전환과 같은 undo 단위 안에서** 다시 그려집니다
(탭을 닫았다 열 필요가 없습니다).

**주의할 점 (에러).**
- 존재하지 않는 에이전트 이름. 대소문자까지 정확히 맞아야 합니다. Claude Code는 못 찾은 이름을
  조용히 `general-purpose`로 돌리기 때문에 Daedalus가 에러로 막습니다.
- `플러그인:이름`인데 그 플러그인을 사용 선언하지 않은 경우
- fork 에이전트로 **워크플로 에이전트**(🤖 탭)를 지목한 경우

**주의할 점 (경고).**
- 스킬과 fork 에이전트의 모델(또는 effort)이 서로 다른 경우. 스킬 값이 이깁니다.

## 🧩 FORK AGENTS — fork 에이전트

**무엇인가.** fork 스킬이 **실행될 자리**입니다. 본문이 그 실행의 시스템 프롬프트가 되고
(fork 스킬 본문은 작업 지시로 옵니다), 도구·모델·`skills` 프리로드·`maxTurns` 같은 설정을
여기서 겁니다.

**🤖 AGENTS와 무엇이 다른가.**

| | 🤖 워크플로 에이전트 | 🧩 fork 에이전트 |
|---|---|---|
| 부르는 것 | 캔버스의 호출 포트에서 나가는 선 | `agent:` 칸으로 지목한 fork 스킬 |
| 캔버스 | 놓습니다 | **놓지 않습니다**(드래그 불가) |
| 출력 포트·호출 포트 | 있습니다 | 없습니다 — 결과 갈래는 부르는 fork 스킬이 정합니다 |
| `background`·`isolation` 칸 | 있습니다 | **없습니다**(아래 참고) |
| 산출 파일 | `agents/<이름>.md` | `agents/<이름>.md` (**같습니다**) |

**산출 파일.** 워크플로 에이전트와 같은 `agents/<이름>.md`입니다. 본문 뒤에
"## Invocation Contract"가 붙고 거기에 **자기를 쓰는 fork 스킬 목록**이 들어갑니다.
"## Delegation"·"## Exits"·"## Internal Workflow"는 나오지 않습니다.

**편집기.** 출력/호출 포트 패널 대신 **"🍴 사용하는 fork 스킬"** 읽기 전용 목록이 보입니다.
비어 있으면 "산출은 되지만 아무도 부르지 않습니다"라고 알려 줍니다. 탭 접두는 🧩입니다.

**`background`·`isolation` 칸이 없는 이유.** 백그라운드 여부는 **fork 스킬 종류**가 정하고
(동기/비동기), `isolation: worktree`는 **fork 실행에 적용되지 않습니다**(Claude Code 2.1.268에서
실측, 2.1.274에서 재확인 — 같은 에이전트를 직접 스폰하면 워크트리가 생기지만 fork로 돌리면
생기지 않습니다). 적용되지 않는 칸을 두면 걸어 둔 제약이 조용히 사라지므로 아예 없앴습니다.

**주의할 점.**
- 어떤 fork 스킬도 이 에이전트를 부르지 않으면 **경고**입니다. 파일은 나가지만 아무도 실행하지 않습니다.
- 삭제할 때 이 에이전트를 쓰는 fork 스킬이 있으면 확인 다이얼로그가 그 목록을 보여 줍니다.

## 📄 DECLARATIVE — 선언형 스킬

**무엇인가.** 절차가 아니라 **배경 지식**입니다. 예: 팀 코딩 규칙, 도메인 용어집, API 사용 규약.

**산출 파일.** `SKILL.md`. 그리고 **프로젝트의 모든 에이전트 `skills` 목록에 자동으로 들어갑니다.**
서브에이전트는 메인 대화의 지식을 물려받지 않으므로, 배경 지식은 따로 넣어 줘야 하기 때문입니다.

**언제 쓰나.**
- 여러 단계·여러 에이전트가 함께 알아야 하는 규칙
- 여러 전이 스킬이 똑같은 지침을 써야 할 때. 전이 스킬 하나를 재사용하는 대신 공통 부분을 선언형으로 뺍니다.
- 특정 노드 몇 개에만 붙이고 싶은 문서라면 📖 REFERENCE가 낫습니다.

**캔버스.** 놓지 않습니다. 레지스트리에서 드래그할 수 없습니다.

**편집기.** 본문과 프론트매터만 있습니다. 출력 포트는 없습니다. 진입 설정 콤보는 쓸 수 있습니다
(사용자가 `/스킬`로 직접 열어볼 수 있게 할지 정하는 용도).

## ⚡ TRANSFER — 전이 스킬

**무엇인가.** 두 노드 사이의 **전이(화살표) 위에 붙는** 짧은 지침입니다. A → B 전이에 T를 붙이면
실제 흐름은 A → T → B가 됩니다. 입력 하나·출력 하나짜리 중간 단계라고 생각하면 됩니다.

**산출 파일.** `SKILL.md`. 사용자가 슬래시 메뉴로 부를 수는 없고(`user-invocable: false`),
**모델이 앞 스킬의 지시에 따라 부릅니다**(`disable-model-invocation: false`). 이 두 값은 고정입니다. 출발 스킬의 "다음 단계"에
"전이 스킬 T를 따른 뒤 B로 가라"는 지시가 자동으로 들어갑니다. 도착지가 에이전트면 에이전트 `.md`에
"호출자가 T를 먼저 수행했다"는 내용이 들어갑니다.

**언제 쓰나.**
- 넘어가기 전에 꼭 거쳐야 하는 짧은 처리 — 예: "리뷰 통과 후 변경 요약을 블랙보드에 적기",
  "에이전트에 넘기기 전에 입력 파일 정리하기"
- 그 자체로 분기하거나 사용자와 대화해야 한다면 전이 스킬이 아니라 노드(⚙/🍴)로 만드세요.

**캔버스.** 노드로 놓지 않습니다. **전이를 우클릭 → "On Transfer 스킬 설정"**에서 고릅니다.
같은 메뉴의 "새 Transfer Skill 생성..."을 쓰면 만들기와 붙이기가 한 번에 됩니다. 떼어낼 때는
"On Transfer 스킬 해제", 미리보기는 같은 메뉴나 레지스트리 우클릭에서 합니다.

**주의할 점.**
- **전이 스킬 하나는 전이 하나에만** 붙일 수 있습니다. 두 곳 이상에 붙이면 에러입니다.
  같은 지침이 여러 전이에 필요하면 📄 선언형으로 빼세요.
- 전이 스킬은 워크플로상 위치가 아니므로, 진행 기록의 `current`를 바꾸지 않고 메모만 남기도록 산출됩니다.

## 📖 REFERENCE — 참조 스킬

**무엇인가.** 특정 노드에 **붙여서** 쓰는 참조 문서입니다. 예: 리뷰 체크리스트, 출력 템플릿, 스타일 가이드.

**산출 파일.** `SKILL.md`. 사용자가 직접 부를 수 없습니다(`user-invocable: false` 고정).

**언제 쓰나.**
- 일부 노드만 보면 되는 문서 — 예: "리뷰어 에이전트에게만 체크리스트 주기"
- 모든 에이전트가 봐야 한다면 📄 선언형이 더 간단합니다.

**캔버스.** 드래그하면 **참조 노드**가 됩니다. 일반 노드와 달리 **여러 번 놓을 수 있어서** 레지스트리에서
흐려지지 않습니다. 참조 노드를 워크플로 노드와 이어서 "이 노드가 이 문서를 참조한다"고 선언합니다.
- 참조 노드 우클릭: "링크 추가", "링크된 노드 하이라이트", 삭제
- 연결선 우클릭: "참조 연결 삭제"
- 편집기 오른쪽 **🔗 링크된 노드** 패널에서도 "＋ 링크 추가…"로 이을 수 있습니다. 캔버스에 한 번 이상 놓아야 활성화됩니다.

**산출에 반영되는 방식.** 참조 스킬을 **에이전트 노드**에 이으면 그 에이전트의 `skills` 목록에 자동으로 들어갑니다.

## 🔗 WRAPPED — 랩핑 스킬

**무엇인가.** **다른 플러그인의 스킬**을 내 워크플로에 끼워 넣는 포장입니다. 본문은 원본 스킬이 가지고
있고, 여기서는 워크플로 연결(포트·전이)과 프론트매터만 정합니다. 원본을 복사하지 않고 실행할 때 원본을 부릅니다.

**준비.** 먼저 도구 메뉴 "외부 플러그인 카탈로그..."에서 마켓플레이스 폴더를 등록하고,
쓸 플러그인을 **체크(사용 선언)** 합니다. 이 선언이 빌드 결과의 플러그인 의존성(MARKETPLACE는
`plugin.json`의 `dependencies`, LOCAL은 settings의 `enabledPlugins`)이 됩니다.

**후보 행.** 사용 선언한 플러그인의 스킬 중 아직 포장하지 않은 것은 🔗 탭에 **회색 기울임꼴 후보 행**
(`🔗 스킬 (플러그인)`)으로 자동으로 뜹니다. 후보 행은 아직 프로젝트 항목이 아니라서 더블클릭이나 우클릭이
되지 않습니다. **캔버스로 드래그하면** 그 자리에서 랩핑 스킬이 만들어지고 놓입니다.
"+" 버튼으로 빈 랩핑 스킬을 만들고 프론트매터에 `플러그인[@마켓]:스킬`을 직접 적는 방법도 있습니다.

**용도 — 처음 놓을 때 고릅니다.**

| 용도 | 캔버스 | 산출 |
|------|--------|------|
| 워크플로 단계 (State) | 일반 노드, 한 번만 | `SKILL.md` + 실행용 서브에이전트 `agents/<이름>.md` |
| 참조 (Reference) | 참조 노드, 여러 번 | 파일 없음. 이어진 스킬에는 "이 외부 스킬을 참고하라" 지시, 이어진 에이전트에는 `skills` 주입 |

- 외부 스킬은 **항상 서브에이전트 안에서** 실행됩니다. 메인 대화에서 바로 부르면 우리 워크플로를 모르는
  외부 지시가 흐름 중간에 섞이기 때문입니다.
- 한 랩핑 스킬을 두 용도로 동시에 쓸 수는 없습니다. 같은 원본을 두 용도로 쓰려면 랩핑 스킬을 두 개 만드세요.
- 용도를 바꾸려면 편집기의 "용도를 …로 바꾸기" 버튼을 누릅니다. 이미 놓여 있으면 무엇이 지워지는지 먼저 묻습니다.

**편집기.** 본문 편집기 대신 **원본 경로(읽기 전용) + "원본 열기"** 버튼이 있습니다. 워크플로 단계 용도면
출력 포트·에이전트 호출 포트 패널이 있고, 참조 용도면 링크 패널이 있습니다.

**삭제 불가 → 비활성화.** 랩핑 스킬은 레지스트리·캔버스·MCP 어디서도 지울 수 없습니다. 우클릭 메뉴에서
"삭제" 대신 **"비활성화"**가 보입니다(편집기 버튼도 같음). 끄면 빌드 산출에서 빠지지만 원본 경로·설정·배치는
그대로 남아 언제든 다시 켤 수 있습니다. 플러그인 사용 선언은 건드리지 않습니다.

**주의할 점 (경고).**
- 원본 경로가 비었거나 형식이 틀림
- 원본이 사용 선언하지 않은 플러그인을 가리킴 (빌드에 의존성이 안 들어가 실행 때 못 찾습니다)
- 사용 선언했는데 어떤 랩핑 스킬도 쓰지 않음 (일부러 켠 것이면 무시해도 됩니다)
- 마켓 이름 없이 선언함 (`이름@마켓` 형식이어야 LOCAL 배선이 됩니다)
- 비활성인데 캔버스에 남아 있음, 용도와 배치가 어긋남

## 🤖 AGENTS — 에이전트

**무엇인가.** 별도 컨텍스트에서 일하는 서브에이전트입니다. 본문이 에이전트의 시스템 프롬프트가 됩니다.

**산출 파일.** `agents/<이름>.md` (LOCAL은 `.claude/agents/<이름>.md`). 컴파일러가 누가 이 에이전트를
부르는지("Invocation Contract"), 어떤 출구로 끝내야 하는지("Exits")를 그래프에서 읽어 자동으로 적습니다.
`skills` 목록에는 선언형 스킬 전부와 이 에이전트 노드에 이어진 참조 스킬이 자동으로 들어갑니다.

**언제 쓰나.**
- 독립적으로 맡길 수 있는 일, 도구·권한을 따로 제한하고 싶은 일 — 예: "테스트만 돌리는 러너", "읽기 전용 리뷰어"
- 워크플로 단계로 쓰려면 캔버스에 놓고, 스킬의 **에이전트 호출 포트**에서 전이를 잇습니다.
- fork 스킬의 실행 기반이 필요하다면 이 탭이 아니라 🧩 FORK AGENTS에서 만드세요 — 워크플로 에이전트는
  fork 에이전트를 겸할 수 없습니다.
- 단순히 "이 단계를 서브에이전트에서 돌리고 싶다"면 에이전트를 새로 만들기보다 🍴 fork 스킬이 가볍습니다.

**캔버스.** 일반 노드로, 한 번만 놓습니다. 노드 우클릭에 "호출자 목록", "출력 포트 편집…"이 추가로 있습니다.

**편집기 주요 패널.**
- **→ 출력 포트**: 에이전트 결과로 분기할 갈래입니다. 새 에이전트는 `done` 하나로 시작합니다.
- **🤖 Agent Call**: 이 에이전트가 다른 에이전트를 부를 때 쓰는 포트입니다(스킬과 같은 규칙).
- **← 호출자**: 이 에이전트를 부르는 노드 목록입니다. 그래프에서 자동으로 계산되며 읽기 전용입니다.
  무엇을 넘기는지는 호출하는 쪽 포트의 설명에 적습니다.
- 프론트매터: 모델, effort, tools, disallowedTools, permissionMode, skills, memory, color, hooks,
  maxTurns, background, isolation, mcpServers.

**주의할 점.**
- MARKETPLACE 빌드에서는 Claude Code가 플러그인 에이전트의 `hooks`·`mcpServers`·`permissionMode`를 무시합니다.
  편집기가 잠그고 경고도 띄웁니다. 이 기능이 필요하면 LOCAL로 빌드하세요([LOCAL 전용 기능](05-local-only-features.md).
- 에이전트 → 에이전트 호출은 가능하지만, 중간 결과가 메인 대화에 남지 않는다는 경고가 뜹니다.
- 호출 체인이 3단계를 넘으면 **에러**입니다. 이때 fork 스킬도 한 단계로 셉니다.
- 자기보다 **상위 모델**의 에이전트를 부르면 **에러**입니다(haiku < sonnet < opus < fable).

## 🔌 EXTERNAL AGENTS — 외부 에이전트

다른 플러그인이 가진 서브에이전트를 **내 워크플로의 노드로** 씁니다. 🤖 AGENTS와 달리
파일을 만들지 않습니다 — 그 에이전트의 정의는 그 플러그인 것이고, 우리는 "여기서 저것을
부른다"는 사실만 그립니다.

**필드는 셋뿐입니다** — 이름, 설명, 그리고 `source`(`플러그인[@마켓]:에이전트`).
모델·도구·권한 칸이 없는 것은 실수가 아닙니다: 그 값들은 저쪽 파일에 적혀 있고 여기서
바꿀 수 없습니다. 칸을 만들어 두면 채워 넣고도 아무 일이 일어나지 않습니다.

**source를 쓰기 전에 사용 선언을 하세요.** 프로젝트 속성의 외부 플러그인 목록(또는
카탈로그 창)에 그 플러그인이 없으면 경고가 뜹니다 — 선언이 없으면 빌드가 배선을 내보내지
않아 런타임에 그 에이전트를 찾지 못합니다.

**캔버스.** 🤖 AGENTS와 똑같이 놓입니다: 호출자의 **에이전트 호출 포트**에서만 선이
들어오고, 출력 포트로 갈래가 나갑니다.

**출력 포트는 "부른 쪽이 고르는 갈래"입니다.** 외부 에이전트는 이 워크플로도 블랙보드도
모릅니다 — 포트 이름으로 끝내라는 우리 규약을 지킬 수 없습니다. 그래서 산출에는 이렇게
나갑니다: *필요한 맥락을 전부 프롬프트에 담고, 결과 기록은 부른 쪽이 직접 하고, 아래
갈래는 그 보고를 읽고 고르라.* 포트 설명에 "이 갈래는 보고가 어떻게 생겼을 때인가"를
적어 두면 부른 쪽이 정확히 고를 수 있습니다.

**미리보기가 비활성입니다.** 산출 파일이 없으니 미리볼 텍스트가 없습니다 — 이 노드가
산출에 미치는 영향은 **부르는 쪽 스킬/에이전트의 텍스트**에 나타나므로 그쪽을 미리보세요.
(MCP `compile_preview`도 같은 이유를 말하며 거절합니다.)

**source가 비어 있으면 산출은 이름을 지어내지 않습니다.** 형식(`플러그인[@마켓]:이름`)이
어긋나면 경고가 뜨고 컴파일은 그대로 성공하지만, 위임 지시 자리에는 에이전트 이름 대신
*"이 노드의 `source`가 비어 있어 부를 에이전트가 없다 — 추측하지 말고 보고하라"*는 문장이
나갑니다. 노드 이름을 대신 적어 두면 CC가 없는 에이전트를 찾다가 조용히 다른 일을 합니다.

**"원본 열기" 버튼은 없습니다.** 외부 **스킬**(🔗 WRAPPED)은 카탈로그가 원본 SKILL.md를
찾아 열어 주지만, 외부 에이전트 파일은 아직 해소하지 못합니다 — 언제나 "찾지 못했습니다"만
내놓는 버튼 대신 아무것도 두지 않았습니다.

## 어떤 종류를 고를까

| 하고 싶은 것 | 고를 종류 |
|-------------|-----------|
| 워크플로의 한 단계, 사용자와 대화가 필요함 | ⚙ PROCEDURAL |
| 워크플로의 한 단계, 메인 컨텍스트를 아끼고 보고를 기다렸다 분기 | 🍴 SYNC FORK |
| 같은데 **기다릴 필요가 없는** 곁가지 작업 | 🍴⏳ ASYNC FORK |
| 모든 에이전트와 스킬이 알아야 하는 규칙·지식 | 📄 DECLARATIVE |
| 두 단계 사이에서 꼭 거쳐야 하는 짧은 처리 | ⚡ TRANSFER |
| 몇몇 노드(특히 에이전트)만 보면 되는 문서 | 📖 REFERENCE |
| 다른 플러그인의 스킬을 단계로 끼워 넣기 | 🔗 WRAPPED (워크플로 단계 용도) |
| 다른 플러그인의 스킬을 참고 자료로만 붙이기 | 🔗 WRAPPED (참조 용도) |
| 도구·권한·모델을 따로 정한 작업자에게 일을 맡기고 결과로 분기 | 🤖 AGENTS (캔버스에 배치) |
| fork 스킬이 실행될 전용 작업자 정의 | 🧩 FORK AGENTS |
| 다른 플러그인의 **에이전트**를 단계로 끼워 넣기 | 🔌 EXTERNAL AGENTS |
| 여러 전이에 같은 지침을 쓰고 싶음 | 📄 DECLARATIVE (전이 스킬 재사용은 에러) |

헷갈리면 이렇게 판단하세요. **캔버스에서 한 칸을 차지하나?** 차지하면 ⚙/🍴/🍴⏳/🔗/🤖/🔌입니다(🧩은 아닙니다).
**화살표 위에 붙나?** 붙으면 ⚡입니다. **노드 옆에 붙이는 문서인가?** 그러면 📖입니다.
**어디에도 안 놓고 늘 깔려 있어야 하나?** 그러면 📄입니다.
