## 승인 항목 6건

### A1. 평가 루프 연결 (구조적 베팅 — 최대 지렛대)

지금 한계는 "일관된 산문"까지 — 그 산문을 모델이 실제로 따르는지는 아무도
검증하지 않는다. CC의 `claude plugin eval`(평가 스위트 작성·실행·CI)에 물려
고리를 닫는다.

- **핵심: 그래프에서 평가 스켈레톤을 유도한다.** FSM으로 설계했기 때문에 공짜로
  나오는 구조가 차별점이다:
  - 전이 하나 = 검증 가능한 기대 하나 — 각 transfer_on 갈래가 실제로 그 후속
    스킬을 인보크하는가 (갈래 커버리지: 모든 출력 이벤트가 최소 1회 행사).
  - 블랙보드 접근 선언(reads/writes) = 상태 파일 단언 — 해당 클래스 JSON이
    스키마에 맞게 생성/갱신되는가.
  - 진행 기록 규칙 = `state/__progress__.json` 단언 — completed/current/prev가
    규약대로 갱신되는가.
- **선행 조사 필수:** `claude plugin eval`의 스위트 형식(JSON/report)·샌드박스·
  실행 계약을 공식 문서로 확정한 뒤 산출 형상을 설계한다(claude-code-guide
  에이전트 활용). 스펙을 추측으로 박으면 A4가 막으려는 드리프트를 자초한다.
- 산출 위치·컴파일 통합(옵션 플래그? 별도 커맨드?)·MARKETPLACE/LOCAL 차이는
  설계 단계에서 결정 — 이 배치에서는 **설계 문서 + 최소 동작 스켈레톤 배출**까지,
  실행 연동(CI 등)은 후속.

### A3. MCP-우선 저작 강화 (구조적 베팅)

도그푸딩 실측: 편집의 대부분이 MCP 경로(CC가 조작, 사람이 캔버스로 검토)였고
GUI 버그가 비용의 상당분이었다. GUI 표면 확장보다 MCP 도구 완결성에 투자한다.

- **편집 경로 제로 갭 실측:** GUI로만 가능하고 MCP로 불가능한 편집을 전수
  조사해 목록화(예: 블랙보드 필드 단위 편집? 카탈로그? 진입점 프리셋? 엣지
  웨이포인트? 등 — 실측이 우선, 추측 금지). 각 갭에 대해 추가할 도구/파라미터를
  제안하고 승인분을 구현.
- **조회 요약 개선:** get_project/get_component가 큰 프로젝트에서 낭비 없이
  필요한 것만 주는지 점검(WP-BO 부분 접근 정신의 확장).
- 기존 규약 유지: 편집은 전부 CommandStack 경유(undo), 캔버스와 같은 규칙 강제.

### A4. 스펙 드리프트 감시 (빠른 승리 — 최우선)

최대 유지 부채(CC 규격 하드코딩) 방어. 틀린 emit은 도구가 없는 것보다 나쁘다
(조용히 실패하므로).

- SchemaStore `claude-code-settings.json` 스냅샷을 저장소에 **벤더링**
  (`tests/fixtures/` 또는 `docs/specs/` — 위치는 구현 판단, 날짜 기록).
- 테스트: `HookEvent` 31종 = 스냅샷 `properties.hooks` 키 집합,
  `NO_MATCHER_EVENTS` = "does not support matchers" 명시 집합, 훅 핸들러
  `to_json` 키가 `$defs.hookCommand` 속성 집합의 부분집합 — 어긋나면 빨강.
- 스냅샷 갱신 커맨드(스크립트 또는 문서화된 절차) + 갱신 시 diff가 보이게.
- 테스트는 네트워크 무접근(벤더링 스냅샷만 읽는다) — 오프라인 그린 유지.

### A5-lite. 토큰 비용 리포트 (빠른 승리)

- `CompileResult`에 산출 파일별 토큰 추정치(간단 휴리스틱 — 문자수/4 수준이면
  충분, 정밀 토크나이저 의존성 추가 금지)와 합계를 담고, 컴파일 다이얼로그·MCP
  `compile_preview`에 표시.
- 임계(예: 스킬당 N 토큰) 초과 시 경고 1줄 — 등급은 정보성(검증 규칙 아님).
- 목적: "자동 단락은 반복 실리는 사용료"(A12 논리)의 계기판 + A5 점진 공개
  (docs/plans/2026-08-25-a5-progressive-disclosure.md, D1~D7 대기)의 착수 근거
  수치 확보.

### A6. 검증 규칙 추가 2종 (빠른 승리)

실사고에서 나온 미구현분:

- **`orphan_hook`** (경고): hook_library의 훅을 어떤 컴포넌트도 참조하지 않음 —
  worker 훅 미작동 사고(훅을 만들고 부착을 잊음)의 재발 방지. 전역 훅(A1 2단
  스코프)은 다른 프로젝트가 쓸 수 있으므로 **프로젝트 훅만** 대상.
- **에이전트/작업 폴더 문서 본문의 스킬 전용 변수** (경고): `$ARGUMENTS`·
  `$ARGUMENTS[N]`·`${CLAUDE_SESSION_ID}`·`${CLAUDE_SKILL_DIR}`가 에이전트 본문
  또는 rules/CLAUDE.md 본문에 등장 — 치환되지 않은 채 산출로 나간다. 변수 팝업
  컨텍스트 필터(1fef2da, variable_loader.variables_for 매트릭스)의 검증기 짝.
  `skill_dir_token_in_agent`가 이미 SKILL_DIR을 짚으므로 **중복 경고 금지**
  (그 규칙을 확장하든 새 규칙에서 SKILL_DIR을 제외하든 구현 판단, 사유 기록).
  코드 표기 제외(`_strip_markdown_code`) 관례 준수.
- 두 규칙 모두: WARNING_RULES 등록 + test_validation_severity.py 분류 + CLAUDE.md
  규칙 표 갱신.

### A7. 시작 템플릿 (빠른 승리)

단순 케이스의 "배보다 배꼽"을 줄이는 가장 싼 방법.

- 아키타입 3종 내외: ① 구현→리뷰 파이프라인(에이전트 2 + 진행 상태 + 블랙보드)
  ② 리서치 파이프라인(병렬 조사 + 합성) ③ 단일 스킬 + 참조 문서.
- 형상: 프로젝트 템플릿(.daedalus.json 시드)을 어디에 두고 어떻게 여는지가 설계
  결정 — 후보: 새 프로젝트 다이얼로그에 템플릿 선택 추가 / File 메뉴 별도 항목 /
  ~/.daedalus/templates/. 본문은 영어(A12 — 산출로 나가는 사용자 값의 출발점이
  되므로), 이름·설명은 플레이스홀더.
- 템플릿 자체가 검증 통과(F7 무에러)해야 한다 — 테스트로 고정.
