## 기본 전제 (사용자 확정 2026-09-04)

**배포 전이므로 후방 호환은 신경 쓰지 않고 견고함에 집중한다.** "MARKETPLACE 산출은
현행과 바이트 동일"이라는 하위 호환 게이트도 이 전제 아래서는 제약이 아니다 — 지킬
대상(배포된 사용자)이 없다.

## 제안 원문 (사용자)

1. ddls 빌드 시, 프로젝트 로컬 플러그인이고 같은 드라이브인 경우, uv 방식처럼
   특정 폴더에 빌드한 후 필요 폴더를 링크하는 방식으로 변경 가능한가.
   (`.claude/settings.local.json`·`.mcp.json` 등은 링크 대상이 아님 — 없으면
   생성, 있으면 편집이고 프로젝트마다 다를 수 있어서 링크 안 됨)
2. 메타 스킬/에이전트 관련 기능 추가: 로컬 플러그인 전용. 새로 필요한 스킬
   혹은 에이전트를 만드는 기능.

## 실측 결과 (2026-09-02)

### LOCAL 빌드가 작업 폴더에 만드는 것 (현행)

| 경로 | 성격 | 링크 가능성 |
|------|------|------------|
| `.claude/skills/<스킬>/` | 스킬당 폴더 (SKILL.md + skill-files) | 폴더 → junction |
| `.claude/agents/<에이전트>.md` | **개별 파일** | junction 불가 — 하드링크/심링크 |
| `files/`, `schemas/`, `hooks/scripts/` | 폴더 | junction |
| `.mcp.json`, `.claude/settings.local.json` | 병합 편집 | **링크 대상 아님** |

### 링크 실측 (이 머신)

`dir symlink` / `file symlink` / `junction(mklink /J)` / `hardlink` **4종 전부 성공**.
다만 symlink는 개발자 모드·관리자 권한이 필요해 다른 머신에서 실패할 수 있다.
junction(폴더)·하드링크(파일)는 **무권한이지만 같은 볼륨 전용** — 사용자가 짚은
"같은 드라이브" 조건이 정확히 이 제약이다.

### 작업 폴더 → ddls 프로젝트 역매핑 (사용자 질문 Q2)

**현재 존재하지 않는다.** `~/.daedalus/mcp-endpoint.json`에 `project` 필드가 있고
실제 값이 들어 있으나(`.../UePluginMaker/.daedalus.json`), ① 앱이 떠 있을 때만
기록되고 ② **현재 앱에 열린 프로젝트 하나**만 가리킨다. "이 작업 폴더가 어느
프로젝트에서 빌드됐는가"의 역방향 매핑이 아니다.

### 프로젝트 파일을 고칠 명령줄 수단 (사용자 질문 Q1)

**없다.** 콘솔 스크립트는 `daedalus`(GUI 진입점)와 `daedalus-bb`(블랙보드 런타임
상태 전용: read/init/write/validate/list) 둘뿐이다. `daedalus-bb`는 설계상
`daedalus.model`을 임포트할 수 없다(`tests/test_import_contracts.py`가 AST로 강제).
현재 유일한 모델 편집 경로는 **앱 내장 MCP 서버**다.

## WP-LK — 스토어 빌드 + 링크

**흐름:** 항상 `~/.daedalus/builds/<프로젝트>-<경로해시>/`에 전량 빌드 → 같은
볼륨이면 링크, 아니면 복사 + 안내 출력(uv 관례).

**링크 방식:** 폴더 junction / 에이전트 `.md` 하드링크. 둘 다 무권한·같은 볼륨이라
조건이 일치한다.

**링크 단위는 폴더 통째가 아니라 항목별이다.** `.claude/skills/`를 통째로 링크하면
그 프로젝트가 손으로 만든 Daedalus 무관 스킬이 사라진다.

**매니페스트 `.claude/.daedalus-links.json`:** 이번 빌드가 만든 항목 목록 + 소스
프로젝트 경로 + 스토어 경로.

- **관리 항목만 갈아끼우고 나머지는 불가침.**
- 매니페스트에 있는데 이번 빌드에 없는 항목만 제거 → **현행 스테일 잔존 결함이
  해소된다**(지금은 `_copy_files_tree(clear_first=False)`라 삭제된 스킬이 작업
  폴더에 영구히 남는다 — 사용자 파일 삭제 위험 때문에 의도적으로 감수 중이었다).
- 소스 프로젝트 경로를 함께 적으면 위 Q2의 역매핑이 생긴다(지금은 쓰지 않지만
  문은 열어 둔다).

## WP-NS — LOCAL 공유 루트 네임스페이스 (2026-09-02 추가, **선행 과제**)

사용자 의문 "한 프로젝트에 여러 ddls 빌드 플러그인이 세팅된 경우"를 실측한 결과
**링크와 무관하게 지금도 깨져 있다.**

| 경로 | 성격 | 두 플러그인이 만나면 |
|---|---|---|
| `.claude/skills/<스킬>/` | 이름별 | 동명일 때만 충돌 |
| `.claude/agents/<에이전트>.md` | 이름별 | 동명일 때만 충돌 |
| `hooks/scripts/<파일>` | 이름별 | 동명일 때만 충돌 |
| `files/` | 트리 병합 | 같은 상대경로면 충돌 |
| **`schemas/schemas.json`** | **고정 경로 1개** | **두 번째가 조용히 덮어쓴다** |
| **`state/<Class>.json`** | **런타임, 클래스명별** | **동명 클래스면 런타임 충돌** |

`_plan_outputs`가 `PurePosixPath("schemas") / "schemas.json"`으로 박고, 산출 본문이
`daedalus-bb --schemas ${ROOT}/schemas/schemas.json`을 지시한다. A를 깔고 B를 깔면
A의 스키마가 사라지고 A의 스킬이 B의 스키마로 검증한다. 경로 충돌 게이트는 **한 번의
컴파일 안에서만** 돌므로 이걸 못 잡는다.

**구조적 원인:** MARKETPLACE는 플러그인마다 `${CLAUDE_PLUGIN_ROOT}`가 달라 충돌이
없다. 충돌은 **LOCAL이 공유 루트에 평평하게 붓기 때문에만** 생긴다.

**해법 — 공유 루트를 플러그인별로 가른다:**

```
schemas/<플러그인>/schemas.json
state/<플러그인>/<Class>.json
files/<플러그인>/...
hooks/scripts/<플러그인>/...
```

- `${ROOT}` 확장 지점이 하나라 치환 자체는 국소적이다.
- **이미 설치된 플러그인의 산출 문자열이 바뀌는 비호환 변경**이고, `state/`는 런타임
  데이터라 이전 경로에서 옮겨야 한다.
- **WP-LK의 선행 과제다.** junction은 폴더를 통째로 대체하므로 `schemas/`가 공유 루트인
  한 두 플러그인이 동시에 링크할 수 없다. 네임스페이스가 생겨야 각자 junction한다.
- 매니페스트도 같은 이유로 **프로젝트별 키**를 가져야 한다. 단일 목록이면 B의 빌드가
  A의 항목을 스테일로 보고 지운다.

### 확정 설계 (2026-09-04)

**경로 규약**

| 대상 | 새 경로 |
|---|---|
| 블랙보드 스키마 | `schemas/<플러그인>.json` (D6 — 폴더 한 겹 안 판다) |
| 블랙보드 상태 | `state/<플러그인>/<Class>.json` |
| 진행 상태 | `state/__progress__.json` — **경로 불변**, 최상위 키가 플러그인 (D13) |

**양쪽 빌드 타깃 모두에 적용한다 (D12).** `state/`에는 `${ROOT}` 토큰이 붙지 않고 작업
폴더 CWD 기준이라, 마켓플레이스 플러그인이 한쪽에만 끼어도 충돌한다:

> 작업 폴더에 A(마켓플레이스)와 B(LOCAL)가 함께 있으면 스킬 파일은 각자 다른 곳에 살지만
> `daedalus-bb`가 `--state-dir` 없이 불려 **둘 다 `<작업폴더>/state/`를 쓴다.** `Task.json`은
> 스키마가 달라 오염되고, 고정 파일명 `__progress__.json`은 나중에 쓴 쪽만 남는다.

LOCAL만 네임스페이스하는 안은 이 시나리오를 그대로 방치하므로 폐기했다.

**CLI 계약 변경 (D10)**

- `--schemas` **필수화.** positional 고정안은 폐기 — 빠뜨렸을 때 argparse가
  `invalid choice: 'Task'`라는 엉뚱한 메시지를 낸다(첫 인자를 경로로 먹어서). 필수 옵션이면
  `the following arguments are required: --schemas`로 정확히 짚는다.
- **`--state-dir` 기본값을 `--schemas`의 stem에서 유도한다** → `state/<stem>`.
  스키마 경로가 절대경로(`${CLAUDE_PLUGIN_ROOT}/…`)여도 stem만 쓰므로 state는 항상 작업
  폴더 상대다. **인자 하나가 두 경로를 결정하므로 어긋날 수 없다.**
  - 이 유도가 없으면 `--state-dir` 누락이 **조용한 데이터 유실**이 된다(검증도 통과하는
    엉뚱한 위치에 쓴다). `--schemas` 누락은 파일 부재로 시끄럽게 실패하지만 이쪽은 조용하다.

**진행 파일 (D13) — `daedalus-bb progress` 서브커맨드 신설**

`__progress__.json`은 지금 **CLI가 아니라 산문 지시로 손편집**된다. 최상위 플러그인 키를
도입하면 "다른 최상위 키는 건드리지 말라"는 병합을 LLM이 손으로 해야 하고, 놓치면
`{"my-plugin": {...}}`로 파일을 통째 덮어써 남의 진행 상태를 지운다 — 파일시스템 충돌을
파일 안으로 옮기는 셈이다.

그래서 갱신을 CLI가 전담한다. `daedalus-bb`의 기존 **원자적 쓰기 + 낙관적 잠금(A6)**을 그대로
재사용하므로 병합을 코드가 보장하고, 스킬 지시문은 산문 병합 설명 대신 명령 한 줄로 **짧아진다**.

```
daedalus-bb --schemas <path> progress set --current <skill> --completed <skill> --note <text> --prev <skill>
daedalus-bb --schemas <path> progress read
```

플러그인 키는 `--schemas` stem에서 유도한다(위 규약 재사용) — 이름을 따로 넘기지 않는다.

**이는 오래된 부채를 갚는 것이기도 하다.** 블랙보드에 CLI를 만든 이유("말로만 시키면 LLM이
JSON을 손으로 만들다 스키마를 어긴다")가 진행 파일에는 적용된 적이 없다. 플러그인이 하나여도
지금 손편집 중이다.

**주의:** 진행 파일은 `state/` 루트에 남고 블랙보드만 `state/<플러그인>/`로 간다. 한 트리에
네임스페이스 방식이 둘이지만 근거가 있다 — `__progress__.json`은 문서에 명시된 **스키마 밖
규약 파일**이고, 워크스페이스 전체를 한눈에 보는 것이 그 파일의 목적이다.

**기존 런타임 데이터 (D11):** 무시한다. 경고도 내지 않는다(코드 0줄). 문서에 경로 변경 사실만 남긴다.

**변경 지점 실측:** `project_compiler.py` 2줄 / `emit/sections.py` 10줄
(`--schemas`·`--state-dir` 지시, `state/<Class>.json` 목록, 산문 2곳) / `emit/skill.py` 6줄
(`__progress__.json` 갱신 지시 → CLI 명령) / `emit/hooks.py` 1줄(SessionStart `cat`) /
`cli/blackboard.py`(필수화 + stem 유도 + `progress` 서브커맨드).

## WP-MS — 메타 스킬 (**설계자 판정: 불필요. 미승인**)

사용자 결정(D4/D5)까지는 "메타 스킬은 100% 프로젝트 로컬로만 생성하고 FSM에서
배제, 로컬용은 작업 폴더에 직접 쓴다"였다. 이후 사용자가 **"정말 필요한지에 대한
근본적 의문"**을 제기했고, 검토 결과 **만들지 않는 쪽을 권고한다.**

**근거:**

- **CC는 이미 스킬을 만들 줄 안다.** `.claude/skills/foo/SKILL.md`를 쓰라고 하면 쓰고
  프론트매터 형식도 안다. 메타 스킬이 더하는 Daedalus 고유 정보는 "관리 항목을
  건드리지 마라" **한 문단**뿐이다.
- **비용이 그 문단에 비해 크다.** 토글 + 모델 필드 + 직렬화 왕복 + 컴파일 계획 +
  검증 규칙 + UI 체크박스 + 문서 + 테스트.
- **스킬은 description 매칭으로 자동 인보크된다.** "새 스킬을 만든다" 같은 일반적
  서술은 무관한 상황에서도 걸려 컨텍스트를 오염시킨다.

### 대안 — `local_edit_detected` 감지 (권고)

링크 방식이 만드는 실제 함정은 메타 스킬 부재가 아니다:

> 사용자가 `.claude/skills/foo/SKILL.md`를 손으로 고치면 junction이라 **스토어 원본이
> 바뀌고**, 그 프로젝트를 링크한 **다른 모든 작업 폴더에 즉시 전파된다.** 그리고 다음
> 빌드에서 조용히 되돌아간다.

고칠 때 경고가 없고 증상이 엉뚱한 작업 폴더에서 나타나므로 안내문으로 막히지 않는다.

- 매니페스트에 관리 항목별 **해시**를 적는다.
- 다음 빌드에서 해시가 다르면 `local_edit_detected` 경고 — 무엇이 빌드 밖에서
  바뀌었는지 짚고 덮어쓸지 묻는다.

메타 스킬보다 싸고 정확하며 실제 실패를 잡는다. 안내 문구가 필요하면 매니페스트 안
`_note` 필드 + 컴파일 결과 출력이면 충분하다.

## WP-WD — 작업 폴더 문서 (2026-09-04 추가)

`.claude/CLAUDE.md`와 `.claude/rules/*.md`를 **ddls 프로젝트에서 편집**하고 LOCAL
빌드가 작업 폴더로 내보낸다. **사용자 요구는 "편집만 가능하면 됨"** — 생성 로직·마커
병합·자동 합성 없음.

### 확인된 사실 (공식 문서, 2026-09-04)

- `./.claude/CLAUDE.md`는 `./CLAUDE.md`와 동등한 **프로젝트 지침 위치**다.
- `.claude/rules/*.md`는 실재한다. `.md`를 **재귀 탐색**하고, `paths:` 프론트매터가
  없으면 **`.claude/CLAUDE.md`와 같은 우선순위로 매 세션 로드**된다.
- `.claude/rules/`는 **심볼릭 링크를 공식 지원**한다 → WP-LK와 호환.
- CLAUDE.md의 **블록 수준 HTML 주석은 컨텍스트 주입 전에 제거**된다 → 표식 비용 0.

### 모델

```
WorkspaceDoc: id, target(CLAUDE_MD | RULE), name, body
PluginProject.workspace_docs: list[WorkspaceDoc]
```

- `.claude/CLAUDE.md`를 별도 `str` 필드로 두지 않고 `target`만 다른 문서로 취급한다.
  `id`가 생겨 `BodyDocumentRegistry`(WP-BU 본문 undo 스택)를 그대로 쓴다.
- `paths:` 프론트매터는 **모델 필드로 만들지 않는다** — body가 그대로 나가므로 필요하면
  사용자가 본문 맨 위에 직접 쓴다.

### 컴파일 (LOCAL 전용)

- `.claude/rules/<name>.md` ← RULE 문서 각각 (이름별이라 **공존 안전**)
- `.claude/CLAUDE.md` ← CLAUDE_MD 문서. 고정 경로지만 **구역 병합으로 공존한다**(아래).
- MARKETPLACE인데 문서가 있으면 경고 1건 + 미배출(작업 폴더에 쓰는 일이라 원리적 불가).

### CLAUDE.md 구역 병합 (사용자 결정 2026-09-04 — 우회안 폐기)

초기 결정은 "없으면 쓴다 / 있으면 `rules/<name>.md`로 우회"였으나, 사용자가 **플러그인
구역 병합**으로 바꿨다. 우회 분기가 사라지면서 **결정적 산출 원칙의 예외도 함께 사라진다**
— 산출 위치가 항상 `.claude/CLAUDE.md` 하나다.

```markdown
<!-- daedalus:my-plugin open -->
# my-plugin

...문서 본문...
<!-- daedalus:my-plugin close -->
```

- 1줄 HTML 주석 2개로 구역을 만든다. **컨텍스트 비용 0**(주입 전 제거됨, 공식 문서 확인).
- **플러그인마다 자기 구역을 소유**하므로 여러 ddls 플러그인 공존이 구조적으로 해결된다
  — `.claude/CLAUDE.md`가 "100% 확정 충돌 항목"에서 빠진다.
- 구역 밖은 손대지 않는다. 구역은 표식으로 식별되므로 **멱등**이고 2회차 뒤집힘이 없다.
- `.mcp.json`·`settings.local.json`과 같은 **병합 편집 부류** → **링크 대상 아님**
  (WP-LK가 그은 선과 일치).
- 플러그인 이름은 컴파일 게이트가 `^[a-z0-9][a-z0-9-]*$`를 강제하므로 표식 파싱에
  정규식 이스케이프 위험이 없다.

**손상 입력 처리 — 파일을 먹는 사고가 나는 지점이다.**

| 상황 | 동작 |
|---|---|
| open만 있고 close 없음 | **건드리지 않고 경고.** 끝을 추측해 뒤를 날리는 일이 절대 없어야 한다 |
| 같은 플러그인 open이 2개 이상 | 손상으로 보고 건드리지 않고 경고 |
| close가 open보다 앞 | 동일 — 건드리지 않고 경고 |

정상 구역은 **제자리에서 내용만 교체**한다(위치 보존). 구역이 없으면 파일 끝에 덧붙이고,
파일 자체가 없으면 새로 만든다. **새로 만들 때도 표식 2줄을 반드시 남긴다**(사용자 확정)
— 표식 없이 쓰면 다음 빌드가 그 파일을 남의 것으로 보고 구역을 또 덧붙인다.

**H1은 `WorkspaceDoc.name`을 쓴다**(기본값 = 프로젝트 이름). 우회 경로가 없어져 `name`의
용도가 "우회 파일명"에서 "구역 제목"으로 바뀐다 — 필드는 그대로다.

**설계자가 정한 기본값(미확정, 변경 가능):**
- 본문이 이미 `# `로 시작하면 H1을 넣지 않는다(중복 제목 방지, 한 줄 판정).
- 문서를 지우거나 비우면 그 구역을 제거한다(플러그인 이름이 키라 멱등). 구역이 없으면
  파일을 열지도 않는다.

`rules/<name>.md`는 종전대로 **파일 하나가 문서 하나**다 — 병합 불필요.

### 부수 효과 — 메타 스킬 논쟁 종결

메타 스킬에 반대하며 남긴 유일한 숙제가 "관리 항목을 손대지 마라"는 경고의 거처였다.
rules 파일이 그 집이다 — 항상 컨텍스트에 있고, description 매칭으로 오발화하지 않으며,
플러그인이 소유한다. **WP-MS는 불필요 판정을 유지한다.**

### 미착수 관찰 — 블랙보드 단락 중복

실측 결과 "## Shared State (Blackboard)" 단락 전체가 **모든 procedural 스킬과 모든
에이전트에 복제**된다(daedalus-bb 사용법 12줄 + 규칙 3줄). rules 파일로 이관하면 스킬
2개 이상 쓰는 워크플로에서 컨텍스트가 줄어든다. 산출 구조가 바뀌는 큰 변경이라 **별도
판단 대상**으로 남긴다.
