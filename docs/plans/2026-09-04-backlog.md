## 1. 착수 가능 — WP-LK (스토어 빌드 + 링크)

설계 확정(D1·D2), 선행 과제였던 WP-NS 완료로 **막힌 것이 없다**.

- `~/.daedalus/builds/<프로젝트>-<경로해시>/`에 전량 빌드 → 같은 볼륨이면 링크,
  아니면 복사 + 안내(uv 관례).
- 폴더는 junction, 에이전트 `.md`는 하드링크. 둘 다 무권한·같은 볼륨 전용.
- `.mcp.json`·`.claude/settings.local.json`·`.claude/CLAUDE.md`는 **링크 대상이
  아니다**(병합 편집 부류).
- 매니페스트 `.claude/.daedalus-links.json` — 관리 항목만 갈아끼우고 나머지는
  불가침. 현행 스테일 잔존 결함(`_copy_files_tree(clear_first=False)`)이 함께 해소된다.

**착수 전 확인 필요:**

| # | 의문 | 왜 중요한가 |
|---|------|------------|
| U2 | junction 삭제 사고 | `shutil.rmtree`가 junction을 따라 들어가 **스토어 원본을 지우는** 고전적 함정. 정리 코드가 링크를 링크로 인식하고 끊기만 해야 한다. 실측 검증 필수 |
| U3 | git·백업·zip 도구 | 링크를 실체 복제하거나 순환할 수 있다. `.gitignore` 안내가 필요한지 |
| U4 | 작업 폴더 이동 | junction은 절대 경로를 담는다. 이동하면 깨진 링크가 남는다 — 감지·안내가 필요한가 |
| U5 | 스토어 GC | 프로젝트를 지우거나 옮기면 스토어가 고아로 남는다 |
| U6 | `${CLAUDE_PROJECT_DIR}` 참조 | 본문이 가리키는 경로가 링크를 타고 스토어에 닿는지 실측 확인 |
| U7 | 이름 충돌 | 사람이 만든 `.claude/skills/foo`와 관리 항목 이름이 겹치면 |
| U8 | 기존 설치분 전환 | 복사로 깔린 작업 폴더를 링크로 바꿀 때 사용자 편집분이 섞여 있으면 |

**대안으로 확정된 것:** 링크 방식의 실제 함정("손으로 고치면 스토어가 오염되고 다른
작업 폴더로 전파된 뒤 다음 빌드에 조용히 롤백")은 **매니페스트 해시 +
`local_edit_detected` 경고**로 친다. 메타 스킬(WP-MS)은 불필요 판정으로 닫혔다 —
`.claude/rules/`가 그 역할을 대신한다.

  구형식 `__progress__.json`은 덮어쓰지 않고 exit 2로 거부하며 안내한다.

## 5. WP-WD 후속

- **컴파일은 규칙 파일을 지우지 않는다.** ddls에서 규칙을 삭제해도 이미 나간
  `.claude/rules/<이름>.md`는 남는다(`delete_rule` 결과 문구에 명시). 매니페스트가
  생기면(WP-LK) 관리 항목으로 정리할 수 있다.
- **표식을 사람이 지우면** 다음 빌드가 구역을 새로 덧붙여 내용이 중복된다. close만
  지우면 손상으로 보고 아무것도 하지 않는다(`unmergeable_claude_md`).
- `claude_md` 문서는 프로젝트를 열자마자 빈 본문으로 생성된다 — 저장 파일에 키가
  생기지만 배출에는 영향이 없다.
